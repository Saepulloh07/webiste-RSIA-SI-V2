================================================================================
1. STANDAR UMUM API & PANDUAN PENGEMBANGAN
================================================================================

1.1 Format Respons Sukses (Standard JSON Success Response)
Setiap permintaan yang berhasil (HTTP 200, 201) WAJIB mengembalikan struktur JSON konsisten:
{
  "success": true,
  "message": "Pesan deskripsi keberhasilan aksi",
  "data": { ... } atau [ ... ],
  "meta": { ... } // Opsional: ada saat pagination
}

1.2 Format Respons Gagal (Standard JSON Error Response)
Setiap permintaan yang gagal (HTTP 400, 401, 403, 404, 422, 500) WAJIB mengembalikan struktur JSON:
{
  "success": false,
  "message": "Pesan deskriptif kesalahan",
  "errors": {
    "field_name": [
      "Pesan validasi field secara spesifik"
    ]
  },
  "code": "ERROR_CODE_STRING" // Opsional
}

1.3 Pagination & Metadata
Untuk request list dengan data banyak, gunakan query params:
  - page: integer (default: 1)
  - limit: integer (default: 10, max: 100)
  - search: string (pencarian teks bebas)
  - sort: string (contoh: "-created_at", "name:asc")
Struktur metadata:
{
  "meta": {
    "page": 1,
    "limit": 10,
    "totalItems": 48,
    "totalPages": 5,
    "hasNextPage": true,
    "hasPrevPage": false
  }
}

1.4 Autentikasi & Autorisasi (JWT)
  - Header Request:
    Authorization: Bearer <access_token>
  - Token Type: JSON Web Token (JWT) dengan signature HS256 atau RS256.
  - Payload Token berisi:
    {
      "sub": "user_uuid_or_id",
      "email": "admin@sayangibu.co.id",
      "role": "Super Admin" | "Admin" | "Editor",
      "exp": 1730000000
    }
  - Role Permissions:
    * Super Admin : Hak akses penuh ke seluruh modul, termasuk manajemen User CMS & Pengaturan Global.
    * Admin       : Hak akses kelola data dokter, layanan, promo, antrean pasien, artikel, media, vacancies.
    * Editor      : Hak akses menulis & mengedit konten artikel dan draft promo/vacancies.

1.5 Kode Status HTTP (HTTP Status Codes)
  - 200 OK           : Permintaan berhasil (GET, PUT, PATCH, DELETE).
  - 201 Created      : Data baru berhasil dibuat (POST).
  - 400 Bad Request  : Parameter request tidak valid atau syntax salah.
  - 401 Unauthorized : Tidak menyertakan token atau token telah kadaluarsa.
  - 403 Forbidden    : Pengguna tidak memiliki role yang diizinkan untuk resource ini.
  - 404 Not Found    : Data/endpoint yang dicari tidak ditemukan.
  - 422 Unprocessable: Validasi field form gagal.
  - 500 Server Error : Terjadi kesalahan fatal pada server backend / database.

2. SKEMA STRUKTUR BASIS DATA (DATABASE SCHEMA & RELATIONS)
================================================================================

Tabel 1: users (Akun Pengelola CMS)
- id            : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- name          : VARCHAR(100) NOT NULL
- email         : VARCHAR(150) NOT NULL UNIQUE
- password_hash : VARCHAR(255) NOT NULL
- role          : ENUM('Super Admin', 'Admin', 'Editor') DEFAULT 'Editor'
- last_login_at : TIMESTAMP NULL
- created_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 2: doctors (Direktori Tenaga Medis & Dokter Spesialis)
- id            : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- name          : VARCHAR(150) NOT NULL (Contoh: "dr. Amanda Saraswati, Sp.OG")
- slug          : VARCHAR(180) NOT NULL UNIQUE (Contoh: "dr-amanda-saraswati-spog")
- specialty     : VARCHAR(100) NOT NULL (Contoh: "Kandungan", "Anak", "Penyakit Dalam")
- subspecialty  : VARCHAR(150) NULL (Contoh: "Fetomaternal, ERACS & Fertilitas")
- status        : ENUM('Aktif', 'Cuti', 'Nonaktif') DEFAULT 'Aktif'
- schedule      : VARCHAR(255) NOT NULL (Contoh: "Senin - Jumat, 08:00 - 14:00")
- sip_number    : VARCHAR(100) NULL (Nomor Izin Praktik)
- poliklinik    : VARCHAR(100) NULL (Lokasi Poli, misal: "Poli Obgyn Lantai 2")
- image_url     : TEXT NULL (URL foto dokter berlatar profesional)
- bio           : TEXT NULL (Biografi & profil keahlian dokter)
- education     : JSON NULL (Array string riwayat pendidikan & sertifikasi)
- created_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 3: services (Layanan Unggulan, Poliklinik & Fasilitas)
- id                : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- name              : VARCHAR(150) NOT NULL (Contoh: "Kandungan & Kebidanan (Obgyn)")
- slug              : VARCHAR(180) NOT NULL UNIQUE (Contoh: "kandungan-kebidanan")
- category          : VARCHAR(100) NOT NULL (Contoh: "Poliklinik", "Penunjang Medis", "Rawat Inap")
- status            : ENUM('Aktif', 'Nonaktif') DEFAULT 'Aktif'
- description       : TEXT NOT NULL (Deskripsi lengkap layanan)
- image_url         : TEXT NULL (URL foto penunjang fasilitas)
- facilities        : JSON NULL (Daftar nama sarana/fasilitas, Array of String)
- operational_hours : VARCHAR(150) NULL (Contoh: "Senin - Sabtu: 08:00 - 20:00")
- created_at        : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at        : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 4: articles (Publikasi Berita & Edukasi Kesehatan)
- id         : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- title      : VARCHAR(255) NOT NULL
- slug       : VARCHAR(255) NOT NULL UNIQUE
- category   : VARCHAR(100) NOT NULL (Contoh: "Kebidanan & Kandungan", "Kesehatan Anak")
- date       : VARCHAR(50) NOT NULL (Format tampilan, misal: "14 Okt 2024")
- status     : ENUM('Published', 'Draft') DEFAULT 'Draft'
- author     : VARCHAR(100) DEFAULT 'Tim Medis RSIA Sayang Ibu'
- content    : LONGTEXT NOT NULL (Isi artikel dalam format HTML / Rich Text)
- image_url  : TEXT NULL (Cover gambar artikel)
- tags       : JSON NULL (Array string kata kunci tag artikel)
- created_at : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 5: ad_campaigns (Promo Layanan & Landing Page Microsite)
- id              : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- title           : VARCHAR(255) NOT NULL
- slug            : VARCHAR(255) NOT NULL UNIQUE
- badge           : VARCHAR(50) DEFAULT 'Promo Spesial'
- price           : VARCHAR(50) NULL (Contoh: "Rp 6.800.000")
- original_price  : VARCHAR(50) NULL (Contoh: "Rp 8.500.000")
- start_date      : DATE NOT NULL
- end_date        : DATE NOT NULL
- status          : ENUM('Aktif', 'Berakhir', 'Draft') DEFAULT 'Draft'
- content         : TEXT NOT NULL (Deskripsi penawaran paket)
- image_url       : TEXT NULL
- highlights      : JSON NULL (Array of String keuntungan paket)
- target_keywords : TEXT NULL (Kata kunci target Google Ads / SEO)
- contact_wa      : VARCHAR(50) NULL (Nomor WA khusus jika beda dari kontak RS)
- created_at      : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at      : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 6: appointments (Pendaftaran Online Pasien / Booking Janji Temu)
- id             : VARCHAR(50) PRIMARY KEY (Contoh: "REG-839201")
- patient_name   : VARCHAR(150) NOT NULL
- phone          : VARCHAR(30) NOT NULL (Nomor WhatsApp/HP)
- patient_type   : ENUM('baru', 'lama') NOT NULL
- payment_method : ENUM('umum', 'bpjs', 'asuransi') NOT NULL
- service_id     : VARCHAR(100) NOT NULL (FK ke tabel services atau id layanan)
- service_name   : VARCHAR(150) NULL
- doctor_id      : VARCHAR(100) NOT NULL (FK ke tabel doctors atau id dokter)
- doctor_name    : VARCHAR(150) NULL
- date           : DATE NOT NULL (Tanggal janji temu yang dipilih)
- time           : VARCHAR(20) NULL (Jam konsultasi yang dijadwalkan)
- notes          : TEXT NULL (Keluhan atau catatan pasien)
- status         : ENUM('Menunggu', 'Dikonfirmasi', 'Selesai', 'Batal') DEFAULT 'Menunggu'
- created_at     : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at     : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 7: job_vacancies (Lowongan Karir & Rekrutmen Medis)
- id            : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- title         : VARCHAR(150) NOT NULL (Contoh: "Perawat Pelaksana (IGD)")
- slug          : VARCHAR(180) NOT NULL UNIQUE
- department    : VARCHAR(100) NOT NULL (Contoh: "Keperawatan", "Medis", "Farmasi")
- type          : ENUM('Full Time', 'Part Time', 'Kontrak') DEFAULT 'Full Time'
- location      : VARCHAR(100) DEFAULT 'Batusangkar'
- experience    : VARCHAR(100) NULL (Contoh: "Minimal 1 Tahun di Rumah Sakit")
- deadline      : DATE NULL
- status        : ENUM('Published', 'Draft') DEFAULT 'Draft'
- description   : TEXT NOT NULL (Uraian tugas dan tanggung jawab)
- requirements  : TEXT NOT NULL (Persyaratan kualifikasi, STR, dll.)
- contact_email : VARCHAR(100) NULL
- contact_wa    : VARCHAR(30) NULL
- date          : VARCHAR(50) NULL
- created_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- updated_at    : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 8: media (Media Library Penyimpanan Berkas & Gambar)
- id          : UUID / BIGINT AUTO_INCREMENT (Primary Key)
- name        : VARCHAR(255) NOT NULL
- type        : ENUM('image', 'video', 'document', 'slideshow', 'website_image') DEFAULT 'image'
- url         : TEXT NOT NULL (URL publik asset di storage / CDN)
- size        : VARCHAR(50) NOT NULL (Contoh: "2.4 MB")
- date        : VARCHAR(50) NOT NULL
- description : TEXT NULL
- created_at  : TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Tabel 9: hospital_settings (Profil & Informasi Resmi Rumah Sakit)
- id              : INT PRIMARY KEY DEFAULT 1
- hospital_name   : VARCHAR(150) NOT NULL DEFAULT 'RSIA Sayang Ibu'
- slogan          : VARCHAR(255) NULL
- about_text      : TEXT NULL
- operational_hours: VARCHAR(150) NULL
- logo_url        : TEXT NULL
- phone_cs        : VARCHAR(50) NULL
- phone_emergency : VARCHAR(50) NULL
- whatsapp        : VARCHAR(50) NULL
- email           : VARCHAR(100) NULL
- address         : TEXT NULL
- maps_url        : TEXT NULL
- maps_embed      : TEXT NULL
- instagram       : VARCHAR(255) NULL
- facebook        : VARCHAR(255) NULL
- youtube         : VARCHAR(255) NULL
- tiktok          : VARCHAR(255) NULL
- updated_at      : TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

Tabel 10: registration_settings (Pengaturan Form Pendaftaran Online)

2.2. PENJELASAN TAHAPAN ALUR PENDAFTARAN:
1. Tahap Inisialisasi & Pemilihan Poli:
   Frontend memanggil endpoint master poliklinik untuk menampilkan poli yang 
   buka/aktif (status = '1').
2. Tahap Pengajuan Booking (Public):
   Pasien mengisi formulir online tanpa kewajiban login terlebih dahulu. Backend 
   memvalidasi kelengkapan data dan memastikan nomor telepon belum terdaftar pada 
   tanggal periksa yang sama. Nomor booking unik diterbitkan dengan format 
   `BP{YYYYMMDD}{4_DIGIT_RANDOM}`.
3. Tahap Sinkronisasi & Verifikasi SIMRS (Internal RS):
   Data booking yang tersimpan di tabel `booking_periksa` ditinjau oleh staf 
   admisi rumah sakit. Staf mengaitkan pasien dengan nomor rekam medis (`no_rkm_medis`),
   menerbitkan nomor antrian dokter (`no_reg`) ke tabel `booking_registrasi` atau 
   `reg_periksa`.
4. Tahap Pengecekan Status Pendaftaran (Self-Service):
   Pasien dapat melacak status konfirmasi menggunakan Nomor Booking dan Nomor Telepon.
   Sistem secara otomatis mengecek kesiapan berkas pendaftaran di SIMRS. Apabila 
   pasien telah didaftarkan di SIMRS, sistem secara otomatis (auto-sync) mengubah 
   status booking menjadi "Diterima" dan menampilkan nomor antrian dokter.
5. Tahap Hari Kunjungan & Monitoring Antrian:
   Pasien dapat melihat posisi antrian langsung di dashboard profil pasien 
   (`my-queue`) maupun memantau display antrian secara live melalui SSE stream.

3.1. FORMAT PENOMORAN:
- Nomor Booking (`no_booking`):
  Format : BP + YYYYMMDD + 4 Digit Random
  Panjang: Maksimal 20 Karakter (String)
  Contoh : BP202609214812
- Nomor Antrian Dokter (`no_reg`):
  Format : 3 Digit Angka dengan Leading Zero (String)
  Sifat  : Per-Dokter per-Poliklinik per-Hari (Dokter A dan B masing-masing mulai 001)
  Contoh : "001", "002", "015"
- Nomor Rawat (`no_rawat`):
  Format : YYYY/MM/DD/xxxxxx (6 Digit Sequence)
  Contoh : 2026/09/21/000001
- Nomor Rekam Medis (`no_rkm_medis`):
  Format : 6 Digit Angka String
  Contoh : "012345"

3.2. STATUS LIFECYCLE & KAMUS ISTILAH:
1. Status Booking (`booking_periksa.status`):
   - 'Belum Dibalas' : Pasien baru mengirim formulir, menunggu admisi RS.
   - 'Diterima'      : Booking telah disetujui / pasien telah masuk antrian SIMRS.
   - 'Ditolak'       : Booking ditolak (misal kuota habis, jadwal dokter tutup).
2. Status Pendaftaran Web (`status_pendaftaran`):
   - 'Belum Terdaftar': Belum masuk ke tabel registrasi SIMRS (`booking_registrasi`).
   - 'Terdaftar'      : Sudah memiliki nomor antrian resmi di SIMRS.
3. Status Pelayanan Rawat Jalan (`reg_periksa.stts`):
   - 'Belum'          : Menunggu dipanggil di poliklinik.
   - 'Berkas Diterima': Pasien sedang dipanggil / berkas masuk ruang dokter.
   - 'Sudah'          : Pemeriksaan oleh dokter telah selesai.
   - 'Batal'          : Pendaftaran dibatalkan.

[GET] /api/queue/stream - Streaming Antrian Real-Time (SSE)
--------------------------------------------------------------------------------
Deskripsi   : Server-Sent Events (SSE) stream untuk menampilkan nomor antrian 
              yang sedang dilayani dan sisa antrian di tiap poliklinik secara live.
Akses       : Publik (Tanpa Autentikasi)
Method      : GET
URL Path    : /api/queue/stream
Header      : Accept: text/event-stream
              Cache-Control: no-cache
              Connection: keep-alive

Mekanisme Real-Time:
- Mengirim initial snapshot saat koneksi dibuka.
- Mendengarkan event internal `queue-updated` ketika pendaftaran baru terjadi.
- Polling otomatis interval 5 detik sebagai sinkronisasi cadangan dari SIMRS desktop.
- Mengirim heartbeat ping `: keep-alive\n\n` tiap 20 detik.
- Kompresi HTTP (gzip/brotli) otomatis dikecualikan untuk menjaga kelancaran stream.

Contoh Format Pesan Data SSE:
data: {"success":true,"data":[{"poli_id":"OBG","poli_name":"POLIKLINIK OBGYN","current_number":"003","total_queue":12,"remaining_queue":4,"status":"OPEN","estimated_wait_time":40},{"poli_id":"ANA","poli_name":"POLIKLINIK ANAK","current_number":"008","total_queue":15,"remaining_queue":2,"status":"OPEN","estimated_wait_time":20}]}


================================================================================
 TABEL DATABASE SIMRS TERKAIT & PEMETAAN
================================================================================

1. TABEL: `booking_periksa` (Model: Booking.js)
   - Kolom:
     * `no_booking`     : varchar(20) [PRIMARY KEY] - Nomor kode booking (BP...)
     * `tanggal`        : date - Tanggal rencana periksa
     * `nama`           : varchar(40) - Nama pasien pendaftar
     * `alamat`         : varchar(200) - Alamat pasien
     * `no_telp`        : varchar(40) - Nomor telepon / WA pasien
     * `email`          : varchar(50) - Email pasien
     * `kd_poli`        : varchar(5) - Foreign Key ke tabel poliklinik
     * `tambahan_pesan` : varchar(400) - Keluhan / pesan tambahan
     * `status`         : enum('Diterima', 'Ditolak', 'Belum Dibalas')
     * `tanggal_booking`: datetime - Waktu saat pasien melakukan submit form (WIB)

2. TABEL: `booking_registrasi` (Model: BookingRegistrasi.js)
   - Kolom:
     * `tanggal_booking`: date - Tanggal booking dibuat
     * `jam_booking`    : time - Jam booking dibuat
     * `no_rkm_medis`   : varchar(15) [PRIMARY KEY] - Nomor Rekam Medis Pasien
     * `tanggal_periksa`: date [PRIMARY KEY] - Tanggal rencana berobat
     * `kd_dokter`      : varchar(20) - Kode dokter yang bertugas
     * `kd_poli`        : varchar(5) - Kode poliklinik tujuan
     * `no_reg`         : varchar(8) - Nomor urut antrian resmi dokter

1. Keamanan & Header:

   - CORS Whitelist:
     * https://cms.sayangibu.co.id
     * https://sayangibu.co.id

   - Tracking Header: Setiap request secara otomatis disematkan header unik 
     `X-Request-ID` (UUID v4) untuk penelusuran audit log.

2. Rate Limiting:
   - Seluruh endpoint `/api/*` dilindungi dengan Rate Limiter:
     Maksimal batas request terdistribusi per-IP dalam window waktu tertentu.
   - Response jika melebihi kuota:
     HTTP Status : 429 Too Many Requests
     Payload     :
     {
       "success": false,
       "error": "Terlalu banyak request, coba lagi dalam 10 menit",
       "retryAfter": 600
     }

3. Daftar Kode Status HTTP yang Digunakan:
   - 200 OK          : Request berhasil diproses.
   - 201 Created     : Pendaftaran/booking baru berhasil dibuat.
   - 400 Bad Request : Data tidak lengkap, format keliru, atau registrasi ganda.
   - 401 Unauthorized: Token otorisasi tidak ada atau tidak valid.
   - 404 Not Found   : Data poliklinik, booking, atau antrian tidak ditemukan.
   - 429 Too Many Req: Request melebihi batas rate limit sistem.
   - 500 Server Error: Kesalahan server internal atau kendala koneksi SIMRS.

4. CONTOH FLOW INTEGRASI FRONTEND-BACKEND
================================================================================

Flow 1: Pendaftaran Online Pasien (Public Booking)
1. Pasien membuka halaman `/pendaftaran` di browser.
2. Frontend memanggil `GET /api/v1/settings/registration` untuk mengecek status form.
   - Jika `isOpen: false`, form dikunci dan pesan pengumuman ditampilkan.
3. Frontend memanggil `GET /api/v1/services` dan `GET /api/v1/doctors?status=Aktif` untuk mengisi dropdown poliklinik dan dokter.
4. Pasien mengisi formulir dan menekan tombol submit.
5. Frontend memanggil `POST /api/v1/appointments` dengan payload data pasien.
6. Backend memvalidasi ketersediaan kuota dan menyimpan data ke database dengan status "Menunggu".
7. Backend mengembalikan No. Registrasi (contoh: "REG-839201").
8. Pasien menerima konfirmasi bukti registrasi di layar.
9. Petugas admin membuka `/admin/appointments`, melihat antrean masuk secara real-time, lalu mengubah status menjadi "Dikonfirmasi" atau "Selesai".

Flow 2: Autentikasi Pengelola CMS
1. Admin mengakses `/login`.
2. Admin memasukkan email dan password, lalu klik Masuk.
3. Frontend mengirimkan `POST /api/v1/auth/login`.
4. Backend memverifikasi hash bcrypt password di database.
5. Jika valid, backend menerbitkan JWT token dan mengembalikan data role akun.
6. Frontend menyimpan JWT token di `localStorage` atau `HttpOnly Cookie`.
7. Setiap request admin berikutnya menyertakan header `Authorization: Bearer <token>`.

5. CHECKLIST DEPLOYMENT & SECURITY UNTUK BACKEND DEVELOPER
================================================================================
[x] 1. CORS Configuration:
       Pastikan backend mengizinkan origin domain frontend, contoh:
       - Development: http://localhost:5173, http://localhost:3000
       - Production : https://sayangibu.co.id, https://www.sayangibu.co.id
[x] 2. Password Hashing:
       Gunakan algoritma bcrypt atau Argon2 dengan cost factor minimal 10. Jangan pernah menyimpan password dalam bentuk plaintext.
[x] 3. Input Validation & Sanitization:
       Sanitasi seluruh input pengguna untuk mencegah SQL Injection dan Cross-Site Scripting (XSS), terutama pada field Rich Text content (artikel).
[x] 4. Rate Limiting:
       Terapkan rate limit pada endpoint publik pendaftaran `POST /api/v1/appointments` dan endpoint login `POST /api/v1/auth/login` (misal: maks 10 request per menit per IP) untuk mencegah spam bot dan brute force.
[x] 5. Upload File Handling:
       - Batasi jenis MIME type hanya gambar (image/jpeg, image/png, image/webp) dan dokumen (application/pdf).
       - Batasi ukuran file maksimal 5 MB.
       - Simpan file ke cloud bucket seperti AWS S3, Cloudflare R2, atau Google Cloud Storage.
[x] 6. Logging & Monitoring:
       Catat aktivitas perubahan status antrean pasien dan penulisan konten oleh pengguna CMS (Audit Trail).
